# 🍩 FSD Strategy

## Purpose

FSD is an evolutionary AI coding assistant.

The objective is to more than just an AI coding assistant. It will dive into a new development identity.

For the project vision, see:

`FSD-CONCEPT.md`

---

# Philosophy

FSD is not a rewrite.

The project should:

- understand before implement;
- preserve before ;
- evolve before redesigning.

Existing behavior represents accumulated knowledge.

---

# Initial Objective

The first objective is identity establish.

FSD should adopt its own identity while becaming an AI coding assistant.

Initial implementations include:

- project naming;
- branding;
- CLI implementation
- skills implementation.

The first stage should avoid unnecessary functional tools.

---

# Evolution Phases

## Phase 1 — Identity

Focus:

- establish FSD terminology.

Goal:

Create the FSD identity.

---

## Phase 2 — Internal Alignment

Focus:

- organize concepts;
- document relationships;
- introduce FSD terminology.

Examples:

Agent → Baker

This is a conceptual mapping.

It does not require immediate technical implementations.

---

## Phase 3 — Capability Evolution

Focus:

- improve workflows;
- enhance developer experience;
- introduce new capabilities;
- optimize execution.

Changes should be introduced incrementally.

---

# Compatibility Strategy

During evolution, FSD should prefer:

- adapters;
- incremental changes;
- compatibility layers;
- reversible improvements.

Avoid:

- large rewrites;
- unnecessary breaking changes;
- replacing working behavior without reason.

---

# Decision Rule

Before implementing behavior, ask:

1. Is the current behavior understood?
2. Is the change necessary?
3. Can it be introduced incrementally?
4. Does it preserve existing value?

If the answer is no, reconsider the change.

---

Should be a life style.
